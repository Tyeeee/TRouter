## 1. 目标与范围

严格执行你确认的 **V1.0 十项验收标准（DoD）**：

| # | 类别 | 验收项 |
|---|---|---|
| C1 | 编译期 | 同一 path 被两个不同类注解 → KSP **编译错误中断构建** |
| C2 | 编译期 | `@Route(path = "/main")` 字面量 → KSP **Warning**（提示引用 RouterContract 常量），不中断 |
| C3 | 编译期 | 每个 group 生成独立 `GroupLoader_<Group>`；`TRouter.init` 后**不加载具体页面类** |
| R1 | 运行时 | `TRouter.navigate(path, bundle)` 成功打开目标 Activity 或 Fragment |
| R2 | 运行时 | 未注册路径 → 触发 `onLost` 降级回调，**不崩溃**，返回 `NotFound` |
| R3 | 运行时 | `isDebug = true` 日志完整输出；`isDebug = false` 日志静默 |
| T1 | 测试 | ActivityScenario + Espresso 真实点击触发导航，禁止白盒直调 navigate |
| T2 | 测试 | `BaseTRouterTest`：`@Before` 重置路由表 / `@After` 释放资源，用例零污染 |
| T3 | 测试 | `testBasicNavigation` / `testLostNavigation` / `testConfigDebugMode` 全绿 |
| O1 | 可观测 | navigate **入口/出口**、GroupLoader **加载开始/结束** 4 个节点输出 `[TRouter]` 日志 |

**V1.0 明确不含**：拦截器（V2.0）、跨进程 AIDL/动态代理/@CrossProcess（V4.0）、动态路由与路由图谱可视化（V5.0）。
因此原「6 大埋点」中拦截器开始/结束、跨进程发送/接收 4 条在 V1.0 不存在，V1.0 只验收上表 O1 的 4 个节点。

**统一治理对照**：统一入口 = 一切行为走 `TRouter` 单例；统一配置 = `TRouterConfig`；统一结果 = `TRouterResult` 密封类（无 null）；统一契约 = `RouterContract` 常量（KSP 对字面量发 Warning）。

## 3. 模块布局与依赖方向（D-1，按你确认：`:app` 保留为主干/测试宿主）

```
TRouterDemo/
├── :trouter-annotation      # 纯 JVM Kotlin 库，零依赖          → com.trouter.annotation
├── :trouter-processor       # 纯 JVM Kotlin 库（KSP 处理器）      → com.trouter.processor
├── :trouter-core            # Android Library（AGP9 内建 Kotlin） → com.trouter.core
└── :app                     # 主干/演示/测试宿主（保留 com.demo.trouter，不动命名）
```

依赖方向（严格单向，杜绝环）：

```
annotation (无依赖)
   ▲
   │ 编译期引用 @Route
app ──► core ──► (androidx.fragment)        # 运行时：TRouter、RouterContract、RouteMeta…
app ──► annotation                          # 页面类上写 @Route
app ── ksp(project(":trouter-processor"))   # KSP 处理 :app 内的 @Route，生成物落在 :app
processor ──► annotation + ksp-api          # 处理器自身只依赖注解与 KSP API
```

- `:trouter-annotation` / `:trouter-processor` 用 `org.jetbrains.kotlin.jvm` 插件（AGP 内建 Kotlin 只管 Android 模块）。
- `:trouter-core` 用 `com.android.library`（AGP 9 内建 Kotlin），**不依赖 annotation**（运行时不读注解，路由信息全部来自生成代码，隔离最干净）。
- `:trouter-remote` 本阶段**不创建**。

## 4. 各模块 API 草案（动工时可能微调，类型契约稳定）

### 4.1 `:trouter-annotation`（仅一个文件 `Route.kt`）

```kotlin
@Target(AnnotationTarget.CLASS)
@Retention(AnnotationRetention.SOURCE)   // 路由表由 KSP 生成，无需 RUNTIME 反射
annotation class Route(val path: String, val group: String = Route.DEFAULT_GROUP) {
    companion object { const val DEFAULT_GROUP = "default" }
}
```

> ⚠ 开放项 A1：`group` 是否给默认值 `"default"`（文档表格写作 `@Route(path, group)` 未提默认）。建议给默认值，演示页更清爽；如需强制显式 group（Fail-Fast 风格）则去掉默认并让 KSP 对缺省不可区分场景报错。默认按「给默认值」设计。

### 4.2 `:trouter-core` `api` 包

| 类型 | 要点 |
|---|---|
| `RouterContract` | V1.0 常量：`PATH_MAIN = "/main"`、`PATH_SECOND = "/second"`、`PATH_UNREGISTERED = "/not/exist"`（演示降级按钮专用，故意不注册）。集中唯一契约源；后续业务路径按里程碑继续沉淀。 |
| `TRouterConfig` | `data class`：`isDebug: Boolean = false`、`logSink: ((String) -> Unit)? = null`、`onLost: ((String) -> Unit)? = null`。`logSink` 用于测试注入日志收集器；`onLost` 为全局降级回调。**V1.0 不含 `enableMockInterceptor`**（拦截器属 V2.0，届时再扩字段，避免死配置）。⚠ 开放项 A2：若你要求 V1.0 就预留该字段，请指出。 |
| `TRouterResult` | 密封类，**禁止 null**：`Success(val meta: RouteMeta)` / `NotFound(val path: String)` / `NotInitialized`。调用方 `when` 穷举失败分支。 |
| `RouteMeta` | 稳定核心数据结构（开闭原则）：`data class RouteMeta(path, group, targetClassName, kind)`，`kind: RouteTargetKind { ACTIVITY, FRAGMENT }`。**只存类名字符串，不存 `Class` 引用** → 支撑惰性加载。 |
| `GroupLoader` / `GroupLoaderRegistry` | `interface GroupLoader { val group: String; fun routeMetas(): List<RouteMeta> }`；`interface GroupLoaderRegistry { fun loaders(): List<GroupLoader> }`。生成代码实现二者。 |
| `TRouter` | 单例 object：`init(context, config)`、`install(registry: GroupLoaderRegistry)`、`navigate(path, bundle: Bundle? = null): TRouterResult`；`internal fun resetForTest()`（core 内可见，供 debug 测试底座调用）。 |

`internal` 包：`RouteTable`（path → meta 注册表）、日志工具（`[TRouter]` + TraceId 结构化输出、受 `isDebug` 控制）、`FragmentContainerActivity`（FRAGMENT 目标承载，见 D-6）。

**注册机制（D-4，请重点评审）**：`TRouter.init(context, config)` 只做核心初始化（配置/日志开关/onLost/空路由表），**不感知任何生成代码**（core 不依赖 app，天然解耦）；路由元数据装配走 TRouter 单例上的**唯一装配 API** `TRouter.install(registry)`，由生成代码 + 宿主一次性调用：

```kotlin
// :app 演示宿主初始化（Application；测试则由 BaseTRouterTest.provideRegistry() 注入，见 §9）
TRouter.init(applicationContext, config)
TRouter.install(TRouterGroupRegistry)     // 生成的 object 聚合注册表（object 引用无需括号），包名见 §6
```

> 备选 D-4b（不推荐）：`init` 内部用 `ServiceLoader`/约定类名自动发现注册表 → 需跨模块拼接类名约定、引入 Android 上 ServiceLoader 合并的坑，V1.0 单宿主场景无收益。

### 4.3 `:trouter-processor`（KSP2，`SymbolProcessorProvider` 经 `META-INF/services` 注册）

职责与生成物见 §6/§7。KSP 版本候选 `2.2.10-2.0.2`（与 Kotlin 2.2.10 配套，构建时以 Maven 实际解析回填版本目录）。

## 6. 生成代码与惰性语义（D-5）

KSP 扫描 `:app` 内所有 `@Route`，按 `group` 分组生成（包 = `trouter.modulePackage` 的 ksp 参数 + `generated`，V1.0 即 `com.demo.trouter.generated`）：

| 生成文件 | 内容 | 说明 |
|---|---|---|
| `GroupLoader_<Group>.kt` | `class GroupLoader_<Group> : GroupLoader`，`routeMetas()` 返回该组 `RouteMeta` 列表 | path 已解析为**字面量**写入；`targetClassName` 为**类名字符串**；`kind` 由处理器判定（见下） |
| `TRouterGroupRegistry.kt` | `object TRouterGroupRegistry : GroupLoaderRegistry`，`loaders()` 返回全部 `GroupLoader_xxx()` | 宿主/测试 `install(...)` 的唯一引用点 |

**惰性解释**（对齐 C3「init 后不加载具体页面类」）：整个 init/install 链路**从不 `Class.forName`、从不引用页面类 `::class`**（生成代码只写字符串）。页面类只在 `navigate()` 真正执行时才 `Class.forName`（成功/失败均记录日志）。`RouteTargetKind` 由处理器沿符号父类型链判定（命中 `android.app.Activity`/`androidx.activity.ComponentActivity` → ACTIVITY；命中 `androidx.fragment.app.Fragment` → FRAGMENT；两者皆非 → KSP ERROR「@Route 目标必须是 Activity 或 Fragment 子类」）。

**FRAGMENT 目标承载（D-6）**：FRAGMENT 路径由 core 内置 `FragmentContainerActivity`（FragmentActivity + 代码生成 container + `Fragment.instantiate(className)`）承接，无需业务容器。⚠ 开放项 A3：首轮 UI 用例建议只演示 Activity 目标（`testBasicNavigation` 跳 `SecondActivity`），Fragment 目标是否在 V1.0 加一个演示用例由你定。

## 7. 编译期校验规则（C1/C2 + Fail-Fast）

| 场景 | 处理 |
|---|---|
| 同一 path 被 ≥2 个类注解（含跨 group） | KSP **ERROR**，列出两个冲突类与来源文件，中断构建（C1） |
| path 为字面量字符串 | KSP **Warning**：`@Route path 请引用 RouterContract 常量`，仍参与生成（C2） |
| path 引用常量（如 `RouterContract.PATH_SECOND`） | 解析常量**字面值**参与冲突检测与生成，无 Warning |
| path 为空 / 含空白 | ERROR |
| 注解目标不是类 / 不是 Activity·Fragment 子类 | ERROR |
| 常量引用无法求值（异常场景，见 R-2） | KSP **Warning** + 该条 path 记为 `__UNRESOLVED_CONSTANT__` + **跳过该条路由的生成**（不注册、不参与运行）+ 处理器日志明确提示「RouterContract 常量无法解析，请检查依赖配置」；被跳过路由在生成报告中列出 |

**常量解析风险（R-2）**：跨模块 `const val`（RouterContract 在 core，编译期是 `:app` 的二进制依赖）能否被 KSP2 求值，社区存在历史 issue（[google/ksp#839](https://github.com/google/ksp/issues/839) 为 Java 注解反向场景）。Kotlin 2.2.10 配套 KSP2（Analysis API）预期可解析编译期常量，但按 Fail-Fast 原则，**实现 Step-2 先做探针**：写一个 `@Route(path = RouterContract.PATH_X)` 的最小模块编译，打印 `KSValueArgument` 求值结果。

**探针失败时的行为是确定性的、可落地的规则**（无模糊空间）：KSP 对该条常量引用输出 Warning，将 path 值记为 `__UNRESOLVED_CONSTANT__`，**跳过该条路由的生成**（不注册、不参与运行），并在处理器日志明确提示「RouterContract 常量无法解析，请检查依赖配置」。该规则已固化在上表最后一行，探针通过与否都不影响后续步骤推进；被跳过的路由会出现在生成报告中，便于定位依赖配置问题。

**多模块局限说明**：KSP 单次运行只看到本 Gradle 模块的注解符号，跨模块（未来 feature 模块各自产路由）的全局冲突检测需后续里程碑引入聚合环节，V1.0 单宿主不受影响。

## 8. 日志与可观测性（O1 + R3）

4 个埋点输出模板（Timber 统一输出，Tag=`TRouter`；消息以 [节点] 开头，不再重复前缀）：

```
[GroupLoader][load][start]        group=default
[GroupLoader][load][end]          group=default routes=1 costMs=…
[navigate][entry] traceId=<id> path=/second bundleKeys=0
[navigate][exit]  traceId=<id> result=Success(meta=/second) costMs=…
[navigate][exit]  traceId=<id> result=NotFound(path=/not/exist) costMs=…   ← 随后触发 config.onLost
```

- `traceId`：每次 `navigate` 生成（入口日志携带并贯穿到出口），GroupLoader 属初始化行为不带 traceId。
- 输出通道：`config.logSink` 为空 → 走 `android.util.Log`；测试注入收集器。
- **R3 语义**：`isDebug = false` 时**跳过全部日志调用**（logSink 也不触发 → 测试可用收集器断言“静默”）。`onLost` 回调不受 isDebug 控制（降级行为始终生效）。

## 9. 测试底座落点（已确认：core 的 debug 变体）

- `:trouter-core/src/debug/kotlin/com/trouter/core/testing/`：`BaseTRouterTest`（抽象 JUnit4 规则类）、`TestConfig`（继承 `TRouterConfig`，注入 logSink 收集器 + onLost 记录器 + `isDebug=true`）。
- `BaseTRouterTest`（抽象类，位于 core 的 debug 源码集，**不引用任何 :app 生成类**，否则 core:debug 编译会因找不到 `TRouterGroupRegistry` 而失败）：
  - 抽象方法 `abstract fun provideRegistry(): GroupLoaderRegistry` —— 由 `:app` 的 androidTest 子类实现并返回生成物 `TRouterGroupRegistry`（:app 的 KSP 生成 object），core:debug 只依赖 `GroupLoaderRegistry` 接口；
  - `@Before` → `TRouter.resetForTest()` + `TRouter.init(ApplicationProvider 上下文, createConfig())` + `TRouter.install(provideRegistry())` + 清空收集器；`@After` → reset 释放；
  - `createConfig()` 可被子类覆写（`testConfigDebugMode` 覆写 `isDebug`），另提供 `reInit(config)` 供用例内切换配置。代码骨架见《V1.0-测试方案》§4.2。
- 说明：core 的 debug 测试依赖（junit4、androidx.test:core 等）经 debug 变体流入 `:app` debug 运行时 —— `:app` 本就是测试宿主，可接受且不进 release。
- 具体用例（3 条）设计见《V1.0-测试方案》§4。
