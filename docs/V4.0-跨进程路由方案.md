# TRouter V4.0 跨进程路由方案（评审稿 v0.1）

> 状态：**评审稿 v0.1 —— 已确认（A1–A6 全采纳推荐）并实施完毕**；实测证据见 `docs/reports/v4/V4.0-TEST-REPORT.md`（26 用例连跑两遍全绿，真实双进程）。
>
> 实施后说明（口径以报告为准）：
> - S11 UI 用例对远端页的**视觉断言**不纳入 Espresso（异进程 Activity 视图不可达），以真实点击 + host 侧 recv 日志断言；远端页展示由手动走查佐证；
> - targetProcess 日志实际输出 `ComponentName.flattenToString()`（§6 示例中的 `:remote` 为概念值）；
> - 远端 NotInitialized 映射 Blocked("remote 未初始化") 由编解码语义固化。

## 1. 术语与边界（先把"跨进程"说清楚）

| 术语 | 定义（本方案） |
|---|---|
| 多进程形态 | **同一 applicationId 内的多进程组件**（demo 内置 `android:process=":remote"` 的第二进程，宿主=演示 app）。不做「跨不同 App」的路由（后者涉签名/权限/白名单，超出 V4 演示价值，列为不含） |
| 跨进程导航 | 进程 A（host）经 **AIDL 服务**把导航请求发给进程 B（remote），**由 B 进程内自己的 TRouter** 解析并打开 B 的本地页面，再把结果摘要返回 A |
| 结果语义 | B 返回「可跨进程传输的结果摘要」→ A 侧重建为统一 `TRouterResult`（Success/NotFound/Blocked/NotInitialized 语义不变，无 null） |

**V4.0 明确不含**：跨 App 路由、动态代理实现（增强项，见 A6）、动态路由/图谱（V5.0）、跨进程 Fragment 直接承载（只承载 Activity 目标，Fragment 跨进程留 A5 裁决）。

## 2. 目标与范围（V4.0 验收清单草案）

| # | 类别 | 验收项 |
|---|---|---|
| C1 | 通道 | core 提供 AIDL 跨进程导航通道：`bind`/`navigate(path,bundle)`/结果回传/解绑；进程内走原单例路径**零回归** |
| C2 | 双进程真实 | demo 内置第二进程 `:remote`：同一 Application（各进程独立 init/install），host 页面可把 /second-remote 类目标发给 remote 进程执行并**真实打开**（不同 PID 佐证） |
| C3 | 统一结果跨进程 | remote 的 Success/NotFound/Blocked 回传后在 host 侧仍是密封 `TRouterResult`（RouteMeta 纯字符串可重建，无 Parcelable 泄漏到业务） |
| C4 | 注册/权限（可选） | `@CrossProcess` 标注 + 编译期校验（只允许标注路由经跨进程通道）——是否纳入见 A2 |

## 3. 架构草案

```
:app (host 进程，pid A)                        :remote 进程（pid B，同一 application）
  TRouter(navigate path, bundle)                 TRouter 实例（Application.onCreate 在各进程独立执行，
      │                                            自动 init + install DemoRouteRegistry，天然就绪）
      ▼
  core IRouterClient
      │ AIDL bind :remote 的 RouterService        RouterService(远端)
      │ navigateRequest(path, bundle) ──────────► 调 TRouter.navigate(path,bundle)（B 进程本地解析+打开）
      │                                             打开目标：B 进程 Activity（android:process 组件）
      ◄──────────── RouterReply(resultKind, path, meta?, reason?, traceId, costMs)
  重建 TRouterResult 并返回调用方
```

- 实现载体：新增 `:trouter-remote` Android Library（core 依赖它或它依赖 core？）放 core 内？——放置见 A1（倾向：core 内新增 `internal` AIDL 通道 + `api` 门面，避免为 MVP 单开模块；`:app` 用 manifest 声明 `:remote` 进程组件并跑同一 TRouterDemoApp）。
- 传输模型：`path: String` + `bundle: Bundle`（AIDL 原生支持）+ 返回自定义 Parcelable `RouterReply`（resultKind 枚举 + path + reason + meta 字段字符串 + traceId + costMs）→ core 侧映射回密封 TRouterResult（RouteMeta 由字符串重建，纯数据无 Class 引用，跨进程天然安全）。
- 生命周期：host 侧 `IRouterClient`（bind 拉活远端 service）懒初始化 + 可解绑；远端不可用/超时 → 返回 `Blocked(path, reason="remote 服务不可用")` 或映射语义（A3 裁决，推荐 Blocked：语义上"通道被拦"，不触发 onLost）。
- 打开方式：远端执行 navigate 时若无前台 UI → 走 appContext + NEW_TASK（跨进程 Activity 由系统栈管理，同 applicationId 同一 UID，`exported=false` 亦可显式启动）。

## 4. @CrossProcess 与编译期校验（A2）

- 若纳入（推荐含）：`:trouter-annotation` 增 `@CrossProcess`（CLASS 级，SOURCE）；处理器扫描新增校验：被 @CrossProcess 标注的类必须同时带 @Route（ERROR 否则）；并生成 `CrossProcessPaths` 白名单常量表供 core 通道校验入参（进程 B 校验：path 未标注 → 拒绝并回 Blocked）。
- 若 A2=不含：MVP 退化为「进程 B 已注册路径即可远程导航」（功能少一道安全闸，接口不变）。
- 处理器仍需聚合修复后的正确性（aggregating=true 已在 V3 修复，跨模块同规则沿用）。

## 6. 埋点（4 → 6 → 8 叙事补全）

```
[navigate][entry/exit]…（既有）  [interceptor][start/eval/end]…（V2 既有）
[remote][send] traceId=<host> path=/remote-second targetProcess=<ComponentName.flattenToString()>
[remote][recv] traceId=<remote> origin=<host traceId> result=Success(meta=/remote-second) costMs=…
[remote][fail] reason=service 未配置 / 白名单拒绝 / 连接超时 / 调用异常
```
- traceId 关联：host 侧发送携 host traceId；remote 回包携带 remote 侧 traceId + origin，二者在日志中可互查（契约用例断言）。
- 进程内 isDebug=false 亦关闭 remote 埋点；跨进程**行为**不受 isDebug 影响（与拦截器/onLost 同级）。

## 8. 风险登记

| # | 风险 | 缓解 |
|---|---|---|
| R-1 | AIDL/多进程在 instrumentation 环境不稳定（bind 竞态、进程拉起时序） | bind 超时+重试窗口；用例对「服务就绪」用显式 await；失败分支本身即验收点 |
| R-2 | 同 applicationId 多进程共享 Application（各进程都 init/install）重复工作/日志翻倍 | 属预期（每进程独立路由表），日志按 pid 区分；文档留痕 |
| R-3 | Bundle 跨进程限制（不可含自定 Parcelable/非 Bundle 类型） | 契约用例只用系统类型（String/Int/boolean…），方案明示边界 |
| R-4 | @CrossProcess 白名单改动波及既有生成/测试 | 白名单独立生成文件，空列表不影响现有行为；aggregating=true 已防增量覆盖 |
| R-5 | 动态代理（roadmap 提及）范围膨胀 | A6 裁决：MVP 不做，仅方案内对比留档 |
