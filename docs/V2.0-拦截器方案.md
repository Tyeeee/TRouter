## 1. 目标与范围（V2.0 验收清单草案）

| # | 类别 | 验收项 |
|---|---|---|
| C1 | 配置 | `TRouterConfig.interceptors` 统一注入；**空列表 = 行为与 V1.0 完全一致**（回归零差异） |
| C2 | 顺序 | 多拦截器按列表顺序执行；`Continue` 放行到下一节点；任一 `Block` 立即终止，**后置拦截器不再执行** |
| C3 | Blocked 结果 | `Block` 时 navigate 返回新密封分支 `TRouterResult.Blocked(path, reason)`：不打开目标、**不触发 onLost**、不崩溃；拦截是行为，**不受 isDebug=false 影响**（R3 语义澄清） |
| C4 | Redirect 改写 | `Redirect(targetPath)` 重新解析目标：已注册 → 继续拦截并打开；未注册 → `NotFound` + `onLost`；累计重定向超过上限 → `Blocked(loop)` 防死循环 |
| C5 | Mock 场景 | core 内置 `MockInterceptor(redirects)`：开关控制 `/second` → mock 页真实重定向（demo 可点可测） |
| C6 | 回归 | V1.0 十用例语义不改仍全绿；日志节点 4 → 6（新增拦截器开始/结束）；出口日志携带 decision |
| O1 | 可观测 | 拦截开始/结束节点输出：拦截器名、次序、decision、costMs |
| T1 | 测试 | UI 行为驱动：真实点击 S08/S09 开关与场景行断言（禁直调 navigate）；契约分支直调 API 归 S10 |
| T2 | 测试 | 沿用 BaseTRouterTest 零污染底座；新增用例不污染既有十例 |

**V2.0 明确不含**：运行时动态增删拦截器 API（有状态拦截器实例已覆盖演示需求，动态化留待后续里程碑评估）、`@Interceptor` 注解级静态拦截、洋葱/后置观察模型（拦截器只做「放行/终止/改写」，无请求-响应双向链）、跨进程 AIDL/动态代理（V4.0）、动态路由与路由图谱（V5.0）。

**统一治理对照**：拦截器配置进 `TRouterConfig`（统一配置）；拦截结果进 `TRouterResult` 密封类（统一结果，无 null）；路径仍引用 `RouterContract` 常量；行为仍全部经 `TRouter.navigate` 单入口。

## 2. 设计要点：拦截时机与决策语义

**拦截点 = 路由解析之后、目标打开之前**（V1.0 navigate 中 `routeTable.find` 与 `openTarget` 之间插入拦截链）：

```
navigate(path, bundle)
  ├─ 未 init                → NotInitialized
  ├─ find 未命中            → NotFound(path) + onLost        ← 不经过拦截器（丢失 ≠ 拦截）
  └─ find 命中 meta
      ├─ 拦截链（有序，任一非 Continue 短路）
      │    Continue            → 下一个拦截器
      │    Block(reason)       → Blocked(path, reason)，终止
      │    Redirect(target)    → 以 target 重新走完整导航（同 traceId，见 §3）
      └─ 全部 Continue        → openTarget(meta) → Success(opened)
```

- 选「解析后」而非「解析前」的理由：拦截器能看到目标**类与分组**（`RouteMeta`），Mock 改写、按目标类门禁才有依据；未注册路径保持 V1.0 丢失语义，拦截器不参与，避免「丢失」与「被拦」混淆。
- **门禁示例**：`GateInterceptor` 按 `meta.path == PATH_SECOND` 门禁 → Block；**Mock 示例**：`MockInterceptor` 命中映射 → Redirect。

## 3. API 草案（`trouter-core` api 包，annotation/processor **零改动**）

```kotlin
// 拦截器：唯一抽象。返回决策，禁止 null。
fun interface RouteInterceptor {
    fun intercept(meta: RouteMeta, bundle: Bundle?): InterceptorDecision
}

// 决策密封类（无 null）：放行 / 终止 / 改写
sealed class InterceptorDecision {
    data object Continue : InterceptorDecision()
    data class Block(val reason: String) : InterceptorDecision()
    data class Redirect(val targetPath: String) : InterceptorDecision()
}

// core 内置：Mock 拦截器（路径 → mock 路径 映射；redirects 之外一律放行）
class MockInterceptor(
    private val redirects: Map<String, String>,
) : RouteInterceptor {
    var enabled: Boolean = false          // 开关：关闭时全放行（行为开关，非日志开关）
    override fun intercept(meta: RouteMeta, bundle: Bundle?): InterceptorDecision =
        if (enabled) redirects[meta.path]?.let { InterceptorDecision.Redirect(it) }
            ?: InterceptorDecision.Continue
        else InterceptorDecision.Continue
}

// TRouterConfig：末尾新增字段，带默认值 → 既有构造调用零破坏
open class TRouterConfig(
    val isDebug: Boolean = false,
    val logSink: ((String) -> Unit)? = null,
    val onLost: ((path: String) -> Unit)? = null,
    val interceptors: List<RouteInterceptor> = emptyList(),   // V2.0 新增
)

// TRouterResult：新增密封子类（编译期强制调用方补充分支，见 §5）
sealed class TRouterResult {
    data class Success(val meta: RouteMeta) : TRouterResult()
    data class NotFound(val path: String) : TRouterResult()
    data object NotInitialized : TRouterResult()
    data class Blocked(val path: String, val reason: String) : TRouterResult()  // V2.0 新增
}
```

- 列表顺序即执行顺序；同一列表内的实例通常由宿主注入有状态对象（门禁开关/映射），**开关走对象自身状态，不走动态增删 API**（见 §1 不含项）。
- `MockInterceptor` 放 core（任何宿主可复用）；`GateInterceptor` 是**业务形态**，放 :app 演示层实现，不进 core。
- Redirect 内部实现：`navigate` 拆为私有 `navigateInternal(path, bundle, traceId, redirectHop)`；**同一次用户导航的 traceId 贯穿所有重定向跳数**，每跳各自记 navigate 入口/出口日志（跳数累加）；`redirectHop > MAX_REDIRECTS(=3)` → 记为 loop，返回 `Blocked(path, "redirect loop")`。
- Redirect 到未注册路径：按「未命中」处理（该跳出口日志 `NotFound`，触发 onLost）。

## 4. 配置与 Mock 的落地形态（回答 V1.0 A2 预留话术）

V1.0 方案曾写「V2.0 再扩 enableMockInterceptor」——本方案改为**不设独立布尔**，理由：若加布尔，则它与 `interceptors` 列表在概念上重复（布尔本质是「把内置 Mock 拦截器挂上」）。统一治理要求一切参数收敛进 `TRouterConfig`，因此：

```kotlin
// :app TRouterDemoApp（演示宿主，isDebug=true）
val mock = MockInterceptor(redirects = mapOf(
    RouterContract.PATH_SECOND to RouterContract.PATH_MOCK_SECOND,   // 新增常量 /mock/second
))
TRouter.init(this, TRouterConfig(
    isDebug = true,
    interceptors = listOf(mock),          // V2.0：演示期挂 Mock；正式宿主自行决定列表
))
```

- 测试/门禁演示同理：`TestConfig` 尾部透传 `interceptors`（见 §7）。
- 新增契约常量 `PATH_MOCK_SECOND = "/mock/second"`，对应新建 mock 页（@Route，group=mock，仅演示期存在——本仓库即演示宿主，语义自洽）。

## 6. 日志节点（4 → 6，Timber，Tag=TRouter，受 isDebug 控制）

新增三条（拦截链每次 navigate 一跳内至多一组；空拦截器列表零日志，行为与 V1.0 逐字节一致）：

```
[interceptor][start] traceId=65eb7626 path=/second interceptors=2
[interceptor][eval]  traceId=65eb7626 index=1 class=GateInterceptor decision=Continue
[interceptor][eval]  traceId=65eb7626 index=2 class=MockInterceptor decision=Redirect(target=/mock/second)
[interceptor][end]   traceId=65eb7626 decision=Redirect(target=/mock/second) costMs=0
[navigate][exit]     traceId=65eb7626 hop=0 result=Redirect(target=/mock/second) costMs=0
[navigate][entry]    traceId=65eb7626 hop=1 path=/mock/second bundleKeys=0        ← Redirect 后新跳（同 traceId）
[interceptor][start] traceId=65eb7626 path=/mock/second interceptors=2
[interceptor][eval]  traceId=65eb7626 index=1 class=GateInterceptor decision=Continue
[interceptor][eval]  traceId=65eb7626 index=2 class=MockInterceptor decision=Continue
[interceptor][end]   traceId=65eb7626 decision=Continue costMs=0
[navigate][exit]     traceId=65eb7626 hop=1 result=Success(meta=/mock/second, kind=ACTIVITY) costMs=…
```

Block 场景（门禁）：

```
[interceptor][start] traceId=b7ce2f4e path=/second interceptors=2
[interceptor][eval]  traceId=b7ce2f4e index=1 class=GateInterceptor decision=Block(reason=演示门禁开启：拦截 /second)
[interceptor][end]   traceId=b7ce2f4e decision=Block(reason=…) costMs=0
[navigate][exit]     traceId=b7ce2f4e hop=0 result=Blocked(path=/second, reason=演示门禁开启：拦截 /second) costMs=1
```

- 拦截器名：日志携带第几个/类名（`meta` 无从取拦截器名，故记 `interceptors=N` 与 class.simpleName）。
- **R3 语义澄清**：isDebug=false 只关日志；拦截**行为**始终生效（与 onLost 同级，属行为而非可观测开关）。
