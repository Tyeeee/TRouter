# TRouter 功能对照核查清单（对开发文档逐条复核）

> **先说人话**：这份清单只回答一个问题——「演示 App 里点不到的，是功能没做，还是做了但界面上没入口？」
> 对照的文档＝各版本的方案文档 + 《版本回顾与缺口核查》。
> 做法是拿这些文档，一条一条去代码里找证据、去演示 App 里找入口、去测试里找用例，不靠口头保证。
> 核对时间：2026-09-05（L4 完成节点）。方法：逐特性 grep 代码 + demo 入口 + 测试证据，非口头保证。

**下面反复出现的几组编号，先一次解释清楚**（后文直接用，不再重复解释）：

- `V1.0`～`V5.0`：这个项目是分五个阶段做的，每个阶段叫一个「版本」，数字越大做得越晚。
- `S01`、`S02`、`S13` 这类编号：演示 App 首页从上往下的场景行编号，点一行就是跑一个场景。
- `C1/C2/C3`、`O1`、`R1`、`T1` 这类：当初定下的验收项编号，只是编号，不是功能名；保留原编号是为了能和旧文档一一对上。
- `L1`～`L4`、`F`、`D`：待办清单里的事项编号（见下面 C 节，逐项都有说明）。
- **「编译门」**＝在**编译阶段**就发现错误、让构建直接失败的检查（不用等到跑起来才发现）。

## B. 各个版本里「本来就没有界面」的场景（demo 上看不到很正常，证据在测试和日志里）

> 「契约」＝把「这个接口应该有什么行为」写成测试固定下来；「洋葱链」＝拦截器像洋葱一样一层包一层，出去要穿过每一层，回来再穿一遍。

| 场景 | 为何无 UI | 证据 |
|---|---|---|
| S05 isDebug 开关 | 由测试注入配置来驱动（演示页没法在运行时改进程内的 config） | testConfigDebugMode |
| S06 主页自身 | 主页本身就是 /main 这条路由 | 启动即覆盖 |
| S07 API 契约（NotInitialized/幂等/traceId/NotFound） | 属于契约类测试，不看界面 | TRouterApiContractTest |
| S10 拦截器契约 | 属于契约类测试 | TRouterInterceptorContractTest |
| S12 跨进程契约（白名单/未配置/远端 NotFound） | 属于契约类测试（真实 AIDL 双进程） | TRouterRemoteContractTest |
| S15 洋葱链契约（L4） | 属于契约类测试 | TRouterOnionChainTest |
