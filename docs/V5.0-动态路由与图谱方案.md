## 1. 目标与范围（V5.0 验收清单草案）

下面这张表就是"这一版做完，拿什么来验收"。表里的 C1–C5／T1／O1 只是验收条目的编号（一眼看出是哪一条），具体是哪件事看"类别"和"验收项"两列。

| # | 类别 | 验收项 |
|---|---|---|
| C1 | 动态注册 | `TRouter` 要提供运行期注册/注销路由的 API（API＝对外提供调用的方法），不依赖 KSP 生成出来的代码（KSP＝在编译期自动生成代码的工具）。注册之后 navigate 要能打开这个页面；注销之后再 navigate 要返回 NotFound |
| C2 | 冲突语义 | 动态注册的 path（path＝路径，也就是"打开哪个页面"的名字）如果和已有的 path（静态的或动态的）撞了，处理方式是**拒绝 + 打告警日志**（要求先 unregister 再注册，这就是 Fail-Fast 的显式语义；Fail-Fast＝一发现问题就马上报错，不闷着往下走），**不做静默覆盖** |
| C3 | 同表共存 | 动态路由和静态路由放在同一张 RouteTable 里共存：拦截器链（拦截器＝跳转前统一跑的一段检查逻辑）、NotFound/onLost、惰性加载、快照/图谱这些机制，全部自动对动态路由生效 |
| C4 | 图谱 | core 模块提供路由图谱模型（节点＝目标类，边＝path 路径），可以从当前路由表实时导出；图里同时包含静态和动态路由 |
| C5 | 可观测 | 注册/注销要输出结构化日志节点；图谱内容要进 `registeredRoutes()` 体系（快照、演示页都能看到） |
| T1 | 测试（本版） | 本版只测 V5：动态注册/注销/冲突/图谱的契约用例 + UI 用例；不跑历史 26 例（统一回测放到最后做） |
| O1 | 可观测 | 图谱要能被 demo 页/测试当成"确定性文本"读出来（含节点数/边数/样例）；确定性＝每次读到的内容和顺序都一样，这样才好断言。用它证明动态和静态在同一个图里 |

**V5.0 明确不含**（这些不在本版范围）：动态路由持久化/热更下发、路由表跨进程同步（remote 进程各自独立表，属跨进程课题边界）、拦截器动态增删（backlog L2＝待办清单第 2 条：运行期增删拦截器）、@Interceptor（backlog L3＝待办清单第 3 条：写在页面上的注解级拦截器）、图谱可视化 SDK（本版只做到 demo 文本/文件导出级）、统一回测（最后执行）。

## 2. API 草案（`trouter-core` api 包；RouteMeta/TRouterResult 零改动）

下面是方法的写法草稿（还没定稿）；`RouteMeta`、`TRouterResult` 这两个类不改。

```kotlin
object TRouter {
    /**
     * 运行时注册路由（V5.0）。与静态生成路由同表共存。
     * @return true 注册成功；false 失败（未初始化 / 重复 path 冲突）
     */
    fun registerRoute(meta: RouteMeta): Boolean

    /** 运行时注销路由（V5.0）：静态与动态均可注销。@return true 确有移除。 */
    fun unregisterRoute(path: String): Boolean

    /** 路由图谱（V5.0）：由当前路由表实时导出的只读模型。 */
    fun routeGraph(): RouteGraph
}

/** 图谱只读模型（api，无 null）：节点=目标类全名，边=path（含来源 kind/group）。 */
data class RouteGraph(
    val nodes: List<String>,            // 目标类全名（含动态注册的类）
    val edges: List<RouteGraphEdge>,    // 每条注册路由一条边
) {
    data class RouteGraphEdge(val path: String, val group: String, val kind: RouteTargetKind, val toClass: String)
}
```

- 实现底座：复用内部的 `RouteTable`（现有的 register 本来就是幂等的；幂等＝同一条数据重复加也不会加出第二份），在外面加一层公开包装 + **冲突检测**（**重复 path** 时：registerRoute 拒绝并打出 `[route][register][conflict]` 日志；推荐用法是 `unregisterRoute` 先删、再注册新的）。
- 复用 `RouteMeta` 意味着：动态注册的目标同样只存**类名字符串**（惰性；惰性＝先只记住类名，真正要用的时候才去加载这个类），所以可以注册任意一个已经存在的 Activity/Fragment 类（比如没标 @Route 的页面）。
- 图谱里的节点按目标类聚合、边按注册路由来；顺序要保证是确定的（按注册次序/快照次序），这样测试才敢断言。
- 初始化/重置的语义：没 init 时 → register/unregister 返回 false 并打日志；`resetForTest()` 会把表清空（动态路由一起清）。

## 5. 风险登记

| # | 风险 | 缓解 |
|---|---|---|
| R-1 | 动态注册会让原来"路由表都是 KSP 静态生成的"这套说法变得含糊（动态 vs 静态：目标类都可能不存在） | registerRoute 不检查类是否存在（保持惰性，和静态一致）；类不存在时，导航时按既有降级逻辑给 NotFound+onLost |
| R-2 | 新增 public API（对外公开的方法）会影响历史测试 | 不改 RouteMeta/TRouterResult/既有 navigate 的语义；冲突检测只对"新注册的路径"生效；历史回测统一放到最后跑 |
| R-3 | 图谱顺序不稳定 | 按路由表的插入顺序导出（LinkedHashMap 语义；LinkedHashMap＝会记住插入顺序的键值表），测试以断言"集合+数量"为主、"顺序"为辅 |
