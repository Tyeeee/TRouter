## 3. 架构修复记录

### 3.1 任务模型 → 同任务导航（2026-09-04 用户反馈：S02 无法返回）

**缺陷**：`TRouter.navigate` 原先一律 `applicationContext + FLAG_ACTIVITY_NEW_TASK` → 每次跳转都进新任务，目标页与主页不在同一返回栈；S02 由 FragmentContainerActivity 承载时它是自己任务的根，按返回键 finish 后只能回桌面，且页内无返回按钮 →「无法返回」。

**修复**（core = 计划中的「生命周期绑定」落地）：
1. `TRouter.init` 注册 `Application.ActivityLifecycleCallbacks`，弱引用追踪当前 resumed Activity；
2. `openTarget` 优先在**当前前台 Activity 的任务内**打开（无 NEW_TASK，返回键/返回栈语义正确）；无前台 UI（通知/无界面）才回退 appContext+NEW_TASK；
3. `FragmentContainerActivity`：`savedInstanceState != null` 时不再重复 commit（重建防护）；
4. DemoFragment 增加「返回」按钮（`requireActivity().finish()`）；
5. MainActivity：singleTask（防实例堆积）、行尾 ›、点击水波纹、顶部交互说明、S06/S05 明确为「说明行」。

**实测验证**（adb 驱动 + dumpsys 焦点核对）：S02/S01/S03 页面按系统返回键后焦点均为 `com.demo.trouter/.MainActivity`（截图 06/07/08-back-*.png）。

### 3.2 运行时反馈 + 系统栏避让（2026-09-04 二轮反馈：S01 看不到 Success、S02 盖状态栏）

- core 新增 `RouteLaunch` 路由元数据键；`openTarget` 打开目标时写入 path/group/kind/traceId/解析耗时；
- Second/About/DemoFragment 读取元数据渲染**运行时证据行**「✓ 本次由 TRouter 打开 · path…· traceId…· 解析 Xms」；无元数据（直连启动）则明示；
- edge-to-edge 系统栏避让：core `FragmentContainerActivity` 与 app 各页（Ui.applyEdgeInsets）均按系统栏 inset 让位；
- 实测：S02 首个元素 top=99px（> 状态栏 ≈63px）不再重叠；S01/S03 页面运行时行可见。
