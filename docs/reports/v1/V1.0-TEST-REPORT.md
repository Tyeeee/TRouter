## 3. 架构修复记录

### 3.1 任务模型 → 同任务导航（2026-09-04 用户反馈：S02 无法返回）

**问题出在哪**：`TRouter.navigate` 原先一律用 `applicationContext + FLAG_ACTIVITY_NEW_TASK` 打开页面 → 每次跳转都进一个新的任务（task），目标页和主页不在同一个返回栈里；S02 由 FragmentContainerActivity 承载时，它就是自己那个任务的根页面，按返回键 finish 之后只能回桌面，而页面里又没有返回按钮 → 用户感受就是「退不回去」。

**怎么修的**（core = 计划中的「生命周期绑定」这次落地）：

1. `TRouter.init` 里注册 `Application.ActivityLifecycleCallbacks`，用弱引用跟踪当前处于 resumed 状态的 Activity；
2. `openTarget` 优先在**当前前台 Activity 所在的任务里**打开（不带 NEW_TASK，返回键和返回栈语义才对）；只有当前没有前台界面（比如通知进来、没有界面）才退回 appContext+NEW_TASK；
3. `FragmentContainerActivity`：`savedInstanceState != null` 时不再重复 commit（防止页面重建时重复添加）；
4. DemoFragment 加了一个「返回」按钮（`requireActivity().finish()`）；
5. MainActivity：singleTask（防止实例堆叠）、行尾 ›、点击水波纹、顶部写清交互说明、S06/S05 明确标成「说明行」。

**实测验证**（用 adb 驱动 + dumpsys 核对焦点）：S02/S01/S03 页面按系统返回键后，焦点都是 `com.demo.trouter/.MainActivity`（截图 06/07/08-back-*.png）。

### 3.2 运行时反馈 + 系统栏避让（2026-09-04 二轮反馈：S01 看不到 Success、S02 盖状态栏）

- core 新增 `RouteLaunch` 路由元数据键；`openTarget` 打开目标时写入 path/group/kind/traceId/解析耗时；
- Second/About/DemoFragment 读取这些元数据，渲染出**运行时证据行**「✓ 本次由 TRouter 打开 · path…· traceId…· 解析 Xms」；如果没有元数据（比如页面是被别的入口直接启动的），就明说没有；
- edge-to-edge 系统栏避让：core 的 `FragmentContainerActivity` 和 app 各个页面（Ui.applyEdgeInsets）都按系统栏的 inset 让出位置；
- 实测：S02 第一个元素 top=99px（大于状态栏的 ≈63px），不再重叠；S01/S03 页面上的运行时行可见。

- 测试：MainRouterTest/TRouterApiContractTest 对齐场景号（没有功能改动，10 个用例两遍全绿）。
