# TRouter V2.0 拦截器 · 测试报告

> **先说人话**
> 这份报告验证的是 V2.0 新加的「拦截器」：也就是"打开页面之前，先统一跑一段检查逻辑"（例如没登录就不让进、维护中就换成兜底页）。
> 主要看四件事：检查能不能按顺序跑、被拦下时会不会真的不开页面、能不能把目标页换成另一个页面、以及老功能有没有被改坏。
> 结论：通过——全量 18 个用例（V1.0 的 10 个语义不动 + V2.0 新增 8 个）连跑两遍全绿（run17 / run18）。
> 状态：**完成待签收**，你签收后才进入 V3.0 规划。

先认几个报告里反复出现的说法：

- **V1.0 / V2.0 / V3.0……**：本项目的里程碑版本号，每个版本加一层能力（V1 基础跳转、V2 拦截器、V3 多模块、V4 跨进程、V5 动态路由）。
- **S08/S09/S10 等**：演示工程主页上的场景编号（S08 是"门禁开关"，S09 是"换页开关"）；**S10-x** 指自动化测试里的第 x 条拦截器用例。
- **C1…C6 / O1 / T1 / T2**：验收清单（DoD）里的编号——C 是功能验收项，O 是可观测性（日志证据），T 是测试方式。
- **A1–A6**：`docs/V2.0-拦截器方案.md` 这份方案里的条目编号。
- **KSP**＝编译期自动生成代码的工具；**Espresso**＝写自动化界面测试用的官方工具；**插桩测试**＝跑在真机/模拟器上的自动化测试；**Bundle**＝Android 传参数的袋子。

## 7. 遗留与说明

1. Redirect 链中，RouteLaunch 元数据反映的是**最终目标页**（比如 /mock/second）；原始 path 没有作为 extra 透传（靠日志和页面横幅来说明），以后需要可以再加。
2. Mock 演示只映射 `/second → /mock/second`（演示用的最小集合）；MockInterceptor 本身是通用的。
3. 动态增删拦截器、@Interceptor 注解级拦截不在 V2.0 范围内（方案 §1 已写明），留给后续里程碑评估。
4. 拦截器日志受 isDebug 控制；拦截**行为**和 onLost 一样属于「行为开关」，不受 isDebug 影响（S10-5 已固化）。
