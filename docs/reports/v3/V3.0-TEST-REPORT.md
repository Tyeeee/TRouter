# TRouter V3.0 多模块路由聚合 · 测试报告

> **先说人话**
> 这份报告验证的是 V3.0 新做的「多模块」：把一个 App 拆成好几个模块后，每个模块自己生成自己的"页面清单"，主模块再把它们汇总起来。
> 主要看三件事：拆开之后跨模块还能不能正常打开页面、每个模块各自生成的清单能不能合并得对、同一个路径被两个模块抢时会不会被发现。
> 顺带挖出并修掉了一个真问题：编译期自动生成代码的工具（KSP＝编译期自动生成代码的工具）在增量编译时，会把页面清单覆盖成残缺的一份（细节见 §4）。
> 结论：通过——全量 20 个用例连跑两遍全绿（run20 / run21）。

先认几个报告里反复出现的说法：

- **V1.0 / V2.0 / V3.0……**：本项目的里程碑版本号，每个版本加一层能力（V1 基础跳转、V2 拦截器、V3 多模块、V4 跨进程、V5 动态路由）。
- **C1…C6 / O1 / T1 / T2**：验收清单（DoD，即"做到哪些事才算完"）里的编号——C 是功能验收项，O 是可观测性（日志证据），T 是测试方式。
- **O1–O5**：`docs/V3.0-多模块路由聚合方案.md` 这份方案里的条目编号。
- **KSP**＝编译期自动生成代码的工具；**loader / 加载器**＝启动时用来加载"某个模块有哪些页面"的那段代码；**插桩测试**＝跑在真机/模拟器上的自动化测试。

## 4. 实施中发现并修复的缺陷（重要）

**KSP 增量生成把聚合输出覆盖成「只有本轮变更的那些符号」**：处理器在 `finish()` 里统一生成 GroupLoader/Registry，但生成依赖声明成了 `aggregating=false`。KSP 增量构建只会把发生变更的文件里的符号喂给处理器 → 新增一个 @Route 页面时，GroupLoader 被重写成只剩新符号（其余路由全没了），跨模块和同模块的冲突检测也随之失效。

- 复现：往 feature-demo 加一个和 `/second` 同 path 的探针类 → 编译**没有**报冲突，而且生成物里丢了 Second/DemoFragment；
- 修复：生成依赖改成 `Dependencies(aggregating = true, *sources)`——只要任何一个 @Route 源文件变了，聚合输出就全量重扫；
- 复验：探针留着 → `compile-gate-duplicate.log` 命中 KSP ERROR「路由路径冲突」；探针移除 → 增量重扫后 loader 恢复完整（`/second`、`/fragment-demo` 两条都在）。

这是 V3.0「每个模块各自产路由」这种工程形态才会暴露的真问题（V1 单模块开发时大多是配置级全量重建，触发不到）。

## 8. 遗留与说明

1. 跨模块的「编译期」冲突检测做不了（KSP 只看得到自己这个模块）；改用「显式聚合 + duplicate 告警 + 唯一性契约」当防线，方案 §7 的 R-1 已写明这个取舍。
2. `RouterContract` 常量值变更（比如 /second → /s2）属于核心模块的二进制变化，不会单独触发 @Route 源重扫——需要一次重建才生效（这是已知且可接受的边界，在此留痕）。
3. Feature 模块各自在自己的 manifest 里声明 Activity，再合并进 :app（exported=false 的语义不变）。
