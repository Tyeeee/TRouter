## 4. 实施中发现并修复的缺陷（重要）

**KSP 增量生成把聚合输出覆盖成「只含本轮变更符号」**：处理器在 `finish()` 统一生成 GroupLoader/Registry，但生成依赖声明为 `aggregating=false`。KSP 增量构建只把变更文件符号喂给处理器 → 新增一个 @Route 页面时，GroupLoader 被重写为只剩新符号（其余路由消失），跨模块/同模块冲突检测同步失效。

- 复现：向 feature-demo 加一个与 `/second` 同 path 的探针类 → 编译**未**报冲突，且生成物丢失 Second/DemoFragment；
- 修复：生成依赖改 `Dependencies(aggregating = true, *sources)`——聚合输出在任一 @Route 源变化时触发全量重扫；
- 复验：探针仍在 → `compile-gate-duplicate.log` 命中 KSP ERROR「路由路径冲突」；移除探针 → 增量重扫恢复完整 loader（`/second`、`/fragment-demo` 两条齐全）。

这是 V3.0「每模块独立产路由」工程形态才暴露的真问题（V1 单模块开发期多为配置级全量重建，未触发）。

## 8. 遗留与说明

1. 跨模块「编译期」冲突检测不可行（KSP 单模块视野）；以「显式聚合 + duplicate 告警 + 唯一性契约」为防线，方案 §7 R-1 已明示取舍。
2. `RouterContract` 常量值变更（如 /second → /s2）属核心模块二进制变化，不会单独触发 @Route 源重扫——需一次重建生效（可接受的已知边界，报告留痕）。
3. Feature 模块各自 manifest 声明 Activity 并合并进 :app（exported=false 语义不变）。
