## 一、这次回测覆盖了什么

按"能不能被机器自动挡住"分成四层，从便宜到贵依次跑：

| 层 | 在检查什么 | 大白话说明 |
|---|---|---|
| ① 编译期闸门 | 页面路径是否被写死、两个模块是否抢同一个路径 | 写错就编译不过，不用等人评审发现 |
| ② 代码检查（Lint） | 调用点是否写死了路径（`TRouter.navigate("/second")`） | 注解里的能查，调用点也能查 |
| ③ 规则自身的单元测试 | 上面那条检查规则本身对不对 | 规则也要有测试，否则拦错了没人知道 |
| ④ 手机端用例（98 个） | 所有功能在真机/模拟器上的真实行为 | 跳转、拦截、异步、跨进程、对象传输…… |
| ⑤ 人工确认（三个进程） | 跨进程是不是真的跨了进程 | 看页面上的进程号和系统进程列表 |

## 二、怎么跑（命令可直接复制）

```bash
# ① 编译期闸门：把"路径写死"当错误处理，全量编译
./gradlew :app:compileDebugKotlin :feature-demo:compileDebugKotlin :feature-about:compileDebugKotlin \
    -PtrouterPathSeverity=error

# ② 跨模块路径冲突检查（插件会自动挂到 check / assemble 上，这里手动跑一次看结果）
./gradlew :app:verifyTRouterRoutes

# ③ 代码检查（含"调用点写死路径"规则）
./gradlew :app:lintDebug

# ④ 检查规则自己的单元测试
./gradlew :trouter-lint:test --rerun-tasks

# ⑤ 手机端全部用例（需要连着模拟器/真机）
./gradlew :app:connectedDebugAndroidTest
```

**跑之前必须做一件事**：把模拟器/手机的动画关掉，否则测试框架会拒绝点击，
症状看起来像"代码坏了"（实际是环境问题）：

```bash
adb shell settings put global window_animation_scale 0
adb shell settings put global transition_animation_scale 0
adb shell settings put global animator_duration_scale 0
```

### 人工确认（跨进程真的跨了进程）

三个进程的进程号互不相同，且页面自己会报出它住在哪个进程：

```
com.demo.trouter          6415     ← 主进程
com.demo.trouter:remote   6485     ← 第二个进程
com.demo.trouter:remote2  7166     ← 第三个进程

页面自述：本页运行在进程 com.demo.trouter:remote2 · pid=7166
```

另外两条肉眼可见的证据：

- 点 S27 后底部状态栏并列显示两个进程各自的接口结果：
  `:remote2 → clock2-v1 q=from-host pid=7166 ｜ 默认(:remote) → -ERR unregistered:demoClock2`
- 点 S29 后：`S29 ✓ count=8 ｜ 远端汇总 tag=s29 level=HIGH sum=6 pid=9023 ｜ report=remote-X/count=99/...`
  （`pid=9023` 就是第三个进程）

## 四、这轮开始前先修掉的一处"老旧断言"

第一次跑全量时 **97/98**，唯一失败的是：
`TRouterApiContractTest#aggregatedRegistryHasNoDuplicatePaths` 写死了"必须正好 6 条路径"，
而后来的功能新增让路径变成 8 条。

处理方式不是把 6 改成 8（下次加页面还会红），而是**改成检查它真正想验证的东西**：

- 没有重复路径（这才是"聚合唯一性"的本意）；
- 关键路径都在；
- **三个模块都必须有贡献**（漏掉某个模块的页面清单，是这类聚合最常见的错误）。

## 五、这次三批改造过程中，测试帮我们发现并修掉的问题

如实记录（都留有日志与提交）：

| # | 问题（大白话） | 怎么发现的 | 处理 |
|---|---|---|---|
| 1 | 用只有新版系统才有的方法，低版本手机会崩 | 开启代码检查后立刻报出 | 改成各版本都安全的写法 |
| 2 | "跳转前要等待"的场景会卡住界面（原实现只能同步等待） | 设计阶段识别 | 新增异步拦截器（可超时、可取消） |
| 3 | 异步拦截器"重复放行"会开两次页面 | 专门写了用例 | 第二次直接报错，显式暴露配置错误 |
| 4 | 超时之后拦截器"迟到放行"会炸掉调用方线程 | 专门写了用例 | 迟到的一律静默忽略 |
| 5 | 加了异步拦截器后，第二进程自带的跳转被误拦，跨进程整条失效 | 回归全量时抓到 | 改成：**能当场放行的异步拦截器不影响普通跳转**，只有"需要等"才要求用异步跳转 |
| 6 | 删除页面后，构建产物里残留旧路径（幽灵路径），会让冲突检查误报 | 采证时观察到一次 | 在检查插件的报错信息里加了排查指引；后续 3 次复现未再出现，留档观察 |
| 7 | 手机端测试源码其实**编译不过**（改了接口没同步改测试替身），"用例全绿"的说法当时并不成立 | 本轮加新用例时立刻暴露 | 补上缺失实现，并从这之后每条结论都以"能编译 + 真跑过"为准 |
| 8 | 生成代码只"生成成功"不等于"能编译"（枚举缺 import、接口方法冲突、参数没强转、Bundle 键名没加引号、对象里不能写 companion） | 每轮都编译整个模块才暴露 | 逐个修掉，并把"改生成器必须编译整模块"写进报告 |

## 六、已知限制与还没做的（不想让人误会）

**功能上还没做的**：

- **模块自动初始化**：现在要你自己在 `Application` 里写各模块的初始化，还没做成"模块自动注册自己"；
- **页面之间的全局事件**：模块间发消息/收消息这类能力没有，需要时先用接口调用（`registerService` / `findService`）。

**使用上的限制（都已在 README 写明）**：

- 还没发布到 Maven 中央仓库，接入要拷源码模块；
- 跨进程传对象：字段类型有白名单，嵌套对象必须和它写在同一个模块，`Date`/`Map` 要自己转；
- 跨进程参数只支持基础类型与字符串（对象请用 `@RemotePojo`）；
- 运行时注册的页面，**也必须在 `AndroidManifest.xml` 里注册过**；
- 手机端用例必须在**关掉动画**的设备上跑。

**验证环境的边界**：本报告的数字来自 macOS + AGP 9.3.2 + Gradle 9.5.0 + Kotlin 2.2.10 + JDK 17 + 模拟器 API 36；
换环境需要重跑（命令同上）。
