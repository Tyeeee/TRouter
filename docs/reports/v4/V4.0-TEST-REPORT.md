## 6. 测试口径说明（诚实留痕）

0. **严重缺陷定位与修复（真实复现，最重要）**：
   现象：首次跨进程点击成功；返回后**再次点击必然 15s 服务超时**（用户实采 logcat：send 23:23:14 → fail 23:23:29 恰为超时窗）。
   根因：`RemoteRouter.navigate` 只把请求放入 pending 队列，唯一派发点是 `onServiceConnected`；**服务已连接时（第二次及以后）没有任何触发点派发新请求** → 请求空等至超时。首次成功只是碰巧走 bind→connect 派发路径。
   修复：navigate 在 ensureConnecting 后追加 `drainIfConnected()`——服务已连接则立即派发全部待处理请求；onServiceConnected 仍负责冷连接后的派发。另将超时窗 8→15s、超时后解除 connecting 悬挂（此前误判为"冷启动慢"，真正根因如上）。
   复验：手动「成功→返回→再点」两次均秒级 Success（logcat #2 recv 23:24:23.322）；自动化回归 **S12-5** 锁死该场景。
   **进一步加固（评审后重写）**：不依赖"在正确位置补一次调用"的顺序论证——RemoteRouter 重写为「单后台线程 trouter-remote + 状态迁移驱动派发」：
   请求入队/连接回调/超时/派发全部在同一 worker 串行执行（无锁无交错）；入队后与连接建立后两个状态点都主动 dispatch，请求入队后只可能走向「真实执行」或「明确 Blocked」，不存在无人派发的盲区；
   binder 跨进程调用移到后台线程，主线程只收 onResult 回调；LogRecorder 同步化以支持多线程写日志；服务中途断开会明确失败等待请求而非静默悬挂。
1. S11 UI 用例的远端页**视觉断言**未纳入 Espresso：远端 Activity 在独立进程，Espresso 只挂接宿主进程窗口，无法直接断言异进程视图（跨进程 pressBack 亦不可用）。改为：真实点击 + host 侧「远端回传 Success 日志」断言（通道全链路真实执行），远端页展示由手动走查 + 截图佐证。
2. 远端未初始化等深水分支未逐一构造（Application 在 :remote 必 init）；NotInitialized 远端映射为 Blocked("remote 未初始化") 由 codec 语义保证（编码层已固化，S12 未单测该构造路径——留注）。

## 8. 遗留与说明

0. **为何跨进程通道是一个 Service（设计说明）**：AIDL 的标准宿主就是**绑定式 Service**（`bindService` + `ServiceConnection` 回调即「服务创建成功后的回调」），manifest 需声明组件与 `android:process`。备选（ContentProvider 信令 / socket）更 hacky 且无标准生命周期回调；动态代理增强同样需要该 bind 底座。**单进程使用 TRouter 完全不需要它**——只有启用跨进程的宿主才声明 `RemoteRouterService`，core 其余能力零依赖。通道实现为「单后台线程 + 状态迁移驱动派发」的状态机（见 §6-0）：服务连接回调只是派发触发点之一，而非唯一派发入口。
1. **动态代理**（roadmap 提及）未实现：A6 决议登记 backlog 增强项（见 `docs/版本回顾与缺口核查.md` L6 拆分）。
2. 跨进程通道只承载 Activity 目标（A5）；Fragment 跨进程目标留后续。
3. remoteService 未配置/白名单拒绝/超时语义均以 Blocked 表达（不触发 onLost），S12-1/2 固化；远端 NotFound 映射见 S12-3。
4. targetProcess 日志实际为 ComponentName.flattenToString（方案 §6 示例的 `:remote` 为概念值，实采见 §5）。
