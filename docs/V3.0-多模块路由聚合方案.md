# TRouter V3.0 多模块路由聚合方案（评审稿 v0.1）

> 状态：**评审稿 v0.1 —— 已确认（O1–O5 全采纳推荐）并实施完毕**；实测证据见 `docs/reports/v3/V3.0-TEST-REPORT.md`（20 用例连跑两遍全绿）。
>
> 实施中发现并修复一个计划外缺陷（已在报告中留痕）：processor 生成依赖原为 `aggregating=false`，KSP 增量会
> 把聚合输出覆盖成「只含本轮变更符号」→ 新增 @Route 页面时 GroupLoader 丢失其余路由、冲突检测失效；
> 修复为 `aggregating=true`（任一 @Route 源变更全量重扫），并以负面编译门复验。另：页面系统栏工具 `Ui` 上移 core api 供跨模块复用。

## 1. 目标与范围（V3.0 验收清单草案）

| # | 类别 | 验收项 |
|---|---|---|
| C1 | 结构 | 路由页面按功能拆到 ≥2 个 feature 模块（Android Library），host(:app) 只留入口页 + 装配 |
| C2 | 生成 | **每个模块独立跑 KSP**：各自生成 `GroupLoader_<Group>` + 模块内注册表 object（包名随模块 namespace） |
| C3 | 聚合 | host 一次性聚合装配全部模块注册表；页面类仍惰性（跨模块 navigate 只存类名、打开时才 Class.forName） |
| C4 | 兼容 | host 自身的 @Route（/main）与 feature 路由共存；单模块内 path 冲突仍是编译 ERROR（C1 验收不变） |
| C5 | 跨模块防线 | 跨模块重复 path（KSP 无法单点拦截）在**聚合装配期可观测**：重复注册告警日志 + 契约测试断言唯一性（first-wins 语义固化） |
| C6 | 回归 | 既有 18 用例（S01–S10）语义不改全绿——仅测试装配点从单注册表换成聚合注册表 |
| T1 | 测试 | 跨模块真实点击（host 主页 → feature 页）行为驱动；聚合唯一性/重复告警契约测试 |
| T2 | 测试 | 既有零污染底座延续；新 feature 模块不产生孤儿路由（场景表全映射） |

## 2. 现状与要解决的缺口

- 现状：`:app` 单模块持有全部 5 个页面（Main/Second/DemoFragment/About/MockSecond），KSP 只在 :app 跑；core 的 `RouteTable.register` 对重复 path 已幂等（跳过并计数）——但**跨模块重复会被静默吞掉**（无日志、无契约保证）。
- 缺口 1：没有「多模块各自产路由、host 聚合」的真实工程示范；
- 缺口 2：跨模块冲突没有可观测防线与测试固化。

## 3. 模块拆分（O1：推荐两 feature 模块）

```
:app (host, com.demo.trouter)           MainActivity(@Route /main) + 聚合装配 DemoRouteRegistry + 全部测试
  └─ :feature-demo (com.demo.trouter.feature.demo)
       SecondActivity  S01 /second           (default)
       DemoFragment    S02 /fragment-demo    (default, FRAGMENT kind 跨模块示范)
       MockSecondActivity S09 /mock/second   (mock)
  └─ :feature-about (com.demo.trouter.feature.about)
       AboutActivity   S03 /about            (secondary)
```

- 页面类原样搬家（纯代码页，无 xml layout 依赖）；Activity 注册从 app manifest 移入各自模块 manifest（AGP manifest 合并，`exported=false` 不变）；包名变更随模块 namespace。
- 每个 feature 模块：`com.android.library` + ksp 插件 + `ksp { arg("trouter.modulePackage", "<模块 namespace>") }`；依赖 `annotation` + `core`（运行时不碰生成物，只实现接口）；fragment 页所在模块补 fragment 依赖。
- RouterContract 仍留 core 共享（全部 path 常量单一来源，feature 注解直接引用常量）。

## 4. 聚合装配（C3/C5）

沿用「唯一装配 API `TRouter.install(registry)` 可多次调用」的既有语义，host 做**源码可见的显式聚合**：

```kotlin
// :app 新增（KSP 生成物 + 各模块注册表在此交汇；GroupLoaderRegistry 只暴露 loaders()）
object DemoRouteRegistry : GroupLoaderRegistry {
    override fun loaders(): List<GroupLoader> =
        com.demo.trouter.generated.TRouterGroupRegistry.loaders() +
        com.demo.trouter.feature.demo.generated.TRouterGroupRegistry.loaders() +
        com.demo.trouter.feature.about.generated.TRouterGroupRegistry.loaders()
}
// TRouterDemoApp：init(config) → install(DemoRouteRegistry) —— 一次聚合装配，路径全部登记
```

- 测试：`provideRegistry(): GroupLoaderRegistry` 从单注册表换成 `DemoRouteRegistry`，BaseTRouterTest / 既有用例断言零改动（隔离与轮次计数走 `loaders().size`，自动覆盖多模块）。
- 重复防线（C5，O3 推荐项）：
  1. `RouteTable.register` 遇到已存在 path 时，install 循环输出 `[RouteTable][duplicate] path=… keep=<先注册的 targetClassName>`（**first-wins 语义固化**；重复 install 同注册表也会如实提示——语义为「该 path 已登记」，可观测优于静默）；
  2. 契约测试：聚合后 `registeredRoutes()` 无重复 path、总数=预期；注入 fake loader 制造跨模块重复 → 断言 duplicate 日志 + first-wins（不崩溃）。
- 不做「跨模块编译期拦截」（见 R-1），在方案中明示取舍。

## 5. 场景与用例

- 场景体系不变（S01–S10）；**S03 与 S01/S02/S09 现分属不同模块**——主页点击跨模块跳转本身即 C1/C3 的 UI 行为证据。
- 新增契约用例（归 S07/S10 同风格新类或并入现有类，O5 未定项小）：
  - `aggregatedRegistryHasNoDuplicatePaths`：聚合注册后唯一性 + 总数（C5 契约）；
  - `duplicateAcrossModulesIsLoggedFirstWins`：fake 重复 → duplicate 日志 + 保留先注册者 + 不崩溃（C5）；
  - 编译门：向 feature 模块注入同 path 重复 @Route 负面样例 → 该模块 KSP ERROR（C4 回归证据，注入后删除）。
- 全量复跑 = 18 旧例 + 新例；T2 隔离两遍绿。

## 7. 风险登记

| # | 风险 | 缓解 |
|---|---|---|
| R-1 | 跨模块 path 冲突无编译期拦截（KSP 单模块视野，聚合编译单元改造面大） | 显式聚合（源码可审）+ 装配期 duplicate 告警 + 契约测试固化唯一性；文档明示该取舍与后续课题 |
| R-2 | 页面搬家改包名波及既有测试引用（注册表 import、manifest 类名、截图） | 测试仅改装配点（provideRegistry）；页面断言文本不变；manifest 条目随类迁移 |
| R-3 | feature 模块 fragment 依赖版本/传递 | feature-demo 显式依赖 fragment 1.8.9（与 core/app 对齐） |
| R-4 | 模块增多致 assemble/install 时间上升 | 仅为编译期模块，无运行时新依赖；沿用 --no-daemon 复跑脚本 |
