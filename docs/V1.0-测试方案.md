## 1. 测试原则（来自项目上下文，严格执行）

四条原则，说白了就是：**像真人一样点，别偷懒直接调接口；每个用例自己收拾干净；每条结论都要留证据。**

1. **行为驱动**：用例模拟真实用户操作 —— `ActivityScenario.launch` → `Espresso.onView(...).perform(click())` → 断言页面跳转/降级反馈。`ActivityScenario` 是启动和操作一个页面的测试工具，Espresso 负责模拟点击。（**禁止**在用例里直接调 `TRouter.navigate` 做白盒断言；白盒＝绕过界面、直接调代码内部接口。）
2. **统一配置**：所有用例都经 `BaseTRouterTest`，在 `@Before`（每条用例开跑前执行的方法）里调用 `TRouter.init(context, TestConfig)`（其中 `isDebug = true`）；禁止绕过初始化去直接操作路由表。
3. **环境隔离**：`@Before` 重置路由状态、`@After`（每条用例跑完后执行的方法）释放资源，用例之间零污染。
4. **证据可复现**：每条验收都附截图/日志片段，汇总成 V1.0 测试报告之后才进入 V2.0。

## 3. 编译期验收（C1/C2/C3）执行流程（不需要设备）

这一步在 Step 5 做完、进入设备测试之前先做。统一由一个小脚本 + 手工截图完成：

```
scripts/verify-compile-gates.sh
 ① 基线：./gradlew :app:kspDebugKotlin        → 期望 0 warning 0 error（全常量引用）
 ② C2：sed 临时把 PATH_SECOND 引用替换为字面量 "/second" → 重跑 → 捕获 Warning 行号 → 还原
 ③ C1：追加 RouteConflictProbe.kt（@Route(path=PATH_SECOND)）→ 重跑 → 捕获编译错误 → 删除文件
 ④ C3：列出 build/generated/ksp/debug/kotlin/.../generated/ 下文件并打印 GroupLoader 内容
```

（`sed` 是命令行里做文本替换的小工具；"基线"＝改任何东西之前先跑一遍，确认本来就是干净的。）

每条失败/通过都留终端截图，存到 `docs/reports/v1/compile-gates/`。这一步没有设备也能做完，所以先向你交付「编译期验收」这一小节。

## 4. 三条 Instrumentation 用例设计

### 4.1 演示页元素契约（`:app`，View 体系，带稳定的 id）

"元素契约"＝测试要靠哪些界面元素来点、来断言，所以 id 和文字要固定下来，测试才稳定。

| 元素 | id / 文本 | 用途 |
|---|---|---|
| 按钮「打开 /second」 | `btn_go_second` | 点击 → `navigate(RouterContract.PATH_SECOND)` → 结果 Success 时不做额外 UI 变化 |
| 按钮「触发未注册路径」 | `btn_go_lost` | 点击 → `navigate(RouterContract.PATH_UNREGISTERED)` → `NotFound` 时更新 `status_text` + 全局 `onLost` 触发 |
| 状态文本 | `status_text` | 默认显示「就绪」；降级后显示「未找到路由:/not/exist」 |
| SecondActivity 标记文本 | 「Second 页面」 | 用来断言目标页确实展示出来了 |
| 可选 ThirdFragment 演示 | 见 ⚠ A3 | FRAGMENT kind 路径 |

### 4.2 `BaseTRouterTest`（core `src/debug`，`com.trouter.core.testing`）

> 关键点：`BaseTRouterTest` 放在 `:trouter-core/src/debug` 里，编译时**看不到 `:app` 的 KSP 生成类**（`TRouterGroupRegistry` 是 :app 生成的）。所以它**不直接引用生成物**，只依赖 core 的接口 `GroupLoaderRegistry`，通过一个抽象方法让 `:app` 的 androidTest 子类把生成物注入进来 —— 这样 core:debug 能独立编译，职责也清楚。

```kotlin
// BaseTRouterTest.kt（trouter-core/src/debug）
abstract class BaseTRouterTest {
  protected val logs = LogRecorder()                    // 实现 config.logSink，记录每条日志
  protected val lostPaths = mutableListOf<String>()     // config.onLost 记录器

  /** 由 :app 的 androidTest 子类返回 KSP 生成物（本类不感知具体类） */
  protected abstract fun provideRegistry(): GroupLoaderRegistry

  @Before fun setUp() {
    TRouter.resetForTest()
    TRouter.init(ApplicationProvider.getApplicationContext(), createConfig())
    TRouter.install(provideRegistry())                 // 子类注入
    logs.clear(); lostPaths.clear()
  }
  @After fun tearDown() { TRouter.resetForTest() }

  /** 默认 TestConfig：isDebug=true + 日志收集 + onLost 记录；子类可覆写 */
  open fun createConfig(): TRouterConfig =
    TestConfig(isDebug = true, logSink = logs, onLost = { lostPaths += it })

  /** 阶段切换（如 testConfigDebugMode）：reset → init(新配置) → install */
  protected fun reInit(config: TRouterConfig) {
    TRouter.resetForTest()
    TRouter.init(ApplicationProvider.getApplicationContext(), config)
    TRouter.install(provideRegistry())
    logs.clear(); lostPaths.clear()
  }
}
```

```kotlin
// MainRouterTest.kt（:app/src/androidTest）—— 由 :app 测试宿主提供生成物
class MainRouterTest : BaseTRouterTest() {
  override fun provideRegistry(): GroupLoaderRegistry = TRouterGroupRegistry  // :app 生成的 object
  // 用例见 §4.3
}
```

- `TestConfig` 是 `TRouterConfig` 的子类/工厂（放在 core 的 debug 变体里），统一把 `isDebug` 设成 `true`。
- 用例本身不碰任何 TRouter API，全部靠点界面来驱动。

### 4.3 用例明细

**T-1 `testBasicNavigation`（R1 + O1）**
```
launch MainActivity →
onView(withId(btn_go_second)).perform(click()) →
onView(withText("Second 页面")).check(matches(isDisplayed()))    // 目标页已开
assertTrue(logs 含 navigate entry(path=/second) 与 exit(Success))
```

**T-2 `testLostNavigation`（R2 + O1）**
```
launch MainActivity →
onView(withId(btn_go_lost)).perform(click()) →
onView(withId(status_text)).check(matches(withText(contains("/not/exist"))))  // 降级 UI
assertEquals(listOf("/not/exist"), lostPaths)                                 // onLost 回调确收
// 进程未崩溃 = 用例本身能继续执行到断言结束
```

**T-3 `testConfigDebugMode`（R3）**
```
阶段 A：默认 createConfig()（isDebug=true）→ launch → 点击 btn_go_second →
        断言 Second 页展示，且 logs ≥ 4 条、含 navigate 出入口与 traceId 字段
close scenario
阶段 B：reInit(TestConfig(isDebug = false, …)) → launch → 点击 btn_go_second →
        断言 Second 页仍正常打开（功能不受日志开关影响）且 logs 为空（静默）
```

> 这里的"阶段 A / 阶段 B"就是同一个用例里的两段场景：A 段开日志、B 段关日志，两段各自走一遍。切换用的是 §4.2 里的 `reInit(config)` 辅助方法（内部就是 reset → init(新配置) → install(provideRegistry())），两段互相隔离，而且注入的注册表是同一个。

## 5. 运行环境与执行（**已锁定：路径 A —— 本机模拟器**）

> "路径 A / 路径 B"指的是两种可选的跑测试环境方案，不是代码里的路径。

### 路径 A（主路径，按这个准备构建配置）

- 前置（进入测试环节第 1 步执行）：先探测本机架构（x86_64 / arm64-v8a）→ `sdkmanager "emulator" "system-images;android-36;google_apis;<abi>"`（下载约 1.5GB+）→ `avdmanager create avd -n trouter_test -k <system-image>`。本机 SDK 已经有 platforms 37.x / build-tools 37，API 36 的镜像和 compileSdk=37 是兼容的（系统镜像的版本不必等于 compileSdk）。
  （`sdkmanager`/`avdmanager`＝Android SDK 自带的"下载组件""创建模拟器"命令行工具；AVD＝Android 虚拟设备，也就是一台配置好的模拟器。）
- 执行：`./gradlew :app:connectedDebugAndroidTest`（第一次跑要下依赖，耗时长，转成后台作业）。
- 截图：各关键断言点由用例内的 `captureScreenshot(name)`（instrumentation screencap 落盘）截，再用 adb 手动 `screencap` 兜一层保险。
- 失败处理：单条红了 → 修 → 单条重跑（`-Pandroid.testInstrumentationRunnerArguments.class=...#方法`）→ 最后全量回归。

### 路径 B（仅兜底：模拟器装不上 / 本机不可用时才切过去）

- 交付全套代码 + 用例 + 报告模板 + 单条运行命令，你在 Android Studio / 真机上跑通后把测试报告 XML 与截图回传（或者允许 agent 经 adb 复核）；切换之前先跟你确认。

### 命令速查

```bash
./gradlew :app:connectedDebugAndroidTest                 # 全量
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=com.demo.trouter.MainRouterTest#testBasicNavigation
adb logcat -d -s TRouter                                  # 日志佐证（O1）
adb exec-out screencap -p > docs/reports/v1/<name>.png    # 截图
```

（`adb`＝Android 官方用来跟设备通信的命令行工具；`logcat` 看日志，`screencap` 截屏。）
