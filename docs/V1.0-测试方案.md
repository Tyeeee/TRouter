## 1. 测试原则（来自项目上下文，严格执行）

1. **行为驱动**：用例模拟真实用户操作 —— `ActivityScenario.launch` → `Espresso.onView(...).perform(click())` → 断言页面跳转/降级反馈；**禁止**在用例内直接调 `TRouter.navigate` 做白盒断言。
2. **统一配置**：所有用例经 `BaseTRouterTest` 在 `@Before` 调用 `TRouter.init(context, TestConfig)`（`isDebug = true`），禁止绕过初始化操作路由表。
3. **环境隔离**：`@Before` 重置路由状态、`@After` 释放资源，用例零污染。
4. **证据可复现**：每条验收附截图/日志片段，汇总为 V1.0 测试报告后才进入 V2.0。

## 4. 三条 Instrumentation 用例设计

### 4.1 演示页元素契约（`:app`，View 体系，带稳定 id）

| 元素 | id / 文本 | 用途 |
|---|---|---|
| 按钮「打开 /second」 | `btn_go_second` | 点击 → `navigate(RouterContract.PATH_SECOND)` → 结果 Success 时无额外 UI |
| 按钮「触发未注册路径」 | `btn_go_lost` | 点击 → `navigate(RouterContract.PATH_UNREGISTERED)` → `NotFound` 时更新 `status_text` + 全局 `onLost` 触发 |
| 状态文本 | `status_text` | 默认「就绪」；降级后显示「未找到路由:/not/exist」 |

### 4.2 `BaseTRouterTest`（core `src/debug`，`com.trouter.core.testing`）

> 关键点：`BaseTRouterTest` 位于 `:trouter-core/src/debug`，编译时**感知不到 `:app` 的 KSP 生成类**（`TRouterGroupRegistry` 由 :app 生成）。因此它**不直接引用生成物**，只依赖 core 接口 `GroupLoaderRegistry`，通过抽象方法让 `:app` 的 androidTest 子类注入 —— core:debug 可独立编译，职责清晰。

```kotlin
// BaseTRouterTest.kt（trouter-core/src/debug）
abstract class BaseTRouterTest {
  protected val logs = LogRecorder()                    // 实现 config.logSink，记录每条日志
  protected val lostPaths = mutableListOf<String>()     // config.onLost 记录器

  /** 由 :app 的 androidTest 子类返回 KSP 生成物（本类不感知具体类） */
  protected abstract fun provideRegistry(): GroupLoaderRegistry

  @Before fun setUp() {
    TRouter.resetForTest()
    TRouter.init(ApplicationProvider.getApplicationContext(), createConfig())
    TRouter.install(provideRegistry())                 // 子类注入
    logs.clear(); lostPaths.clear()
  }
  @After fun tearDown() { TRouter.resetForTest() }

  /** 默认 TestConfig：isDebug=true + 日志收集 + onLost 记录；子类可覆写 */
  open fun createConfig(): TRouterConfig =
    TestConfig(isDebug = true, logSink = logs, onLost = { lostPaths += it })

  /** 阶段切换（如 testConfigDebugMode）：reset → init(新配置) → install */
  protected fun reInit(config: TRouterConfig) {
    TRouter.resetForTest()
    TRouter.init(ApplicationProvider.getApplicationContext(), config)
    TRouter.install(provideRegistry())
    logs.clear(); lostPaths.clear()
  }
}
```

```kotlin
// MainRouterTest.kt（:app/src/androidTest）—— 由 :app 测试宿主提供生成物
class MainRouterTest : BaseTRouterTest() {
  override fun provideRegistry(): GroupLoaderRegistry = TRouterGroupRegistry  // :app 生成的 object
  // 用例见 §4.3
}
```

- `TestConfig` 是 `TRouterConfig` 的子类/工厂（core debug 变体），统一 `isDebug = true`。
- 用例本身不触碰任何 TRouter API，全部经 UI 点击驱动。

### 4.3 用例明细

**T-1 `testBasicNavigation`（R1 + O1）**
```
launch MainActivity →
onView(withId(btn_go_second)).perform(click()) →
onView(withText("Second 页面")).check(matches(isDisplayed()))    // 目标页已开
assertTrue(logs 含 navigate entry(path=/second) 与 exit(Success))
```

**T-2 `testLostNavigation`（R2 + O1）**
```
launch MainActivity →
onView(withId(btn_go_lost)).perform(click()) →
onView(withId(status_text)).check(matches(withText(contains("/not/exist"))))  // 降级 UI
assertEquals(listOf("/not/exist"), lostPaths)                                 // onLost 回调确收
// 进程未崩溃 = 用例本身能继续执行到断言结束
```

**T-3 `testConfigDebugMode`（R3）**
```
阶段 A：默认 createConfig()（isDebug=true）→ launch → 点击 btn_go_second →
        断言 Second 页展示，且 logs ≥ 4 条、含 navigate 出入口与 traceId 字段
close scenario
阶段 B：reInit(TestConfig(isDebug = false, …)) → launch → 点击 btn_go_second →
        断言 Second 页仍正常打开（功能不受日志开关影响）且 logs 为空（静默）
```

> 阶段切换使用 §4.2 的 `reInit(config)` 辅助方法（内部 reset → init(新配置) → install(provideRegistry())），两阶段隔离且注册表注入一致。

## 5. 运行环境与执行（**已锁定：路径 A —— 本机模拟器**）

### 路径 A（主路径，按此准备构建配置）

- 前置（进入测试环节第 1 步执行）：探测本机架构（x86_64 / arm64-v8a）→ `sdkmanager "emulator" "system-images;android-36;google_apis;<abi>"`（下载约 1.5GB+）→ `avdmanager create avd -n trouter_test -k <system-image>`。本机 SDK 已有 platforms 37.x / build-tools 37，API 36 镜像与 compileSdk=37 兼容（system image 无需等于 compileSdk）。
- 执行：`./gradlew :app:connectedDebugAndroidTest`（首次含依赖下载，耗时长，转后台作业）。
- 截图：各关键断言点由用例内 `captureScreenshot(name)`（instrumentation screencap 落盘）+ adb 手动 `screencap` 双保险。
- 失败处理：单条红 → 修 → 单条重跑（`-Pandroid.testInstrumentationRunnerArguments.class=...#方法`）→ 全量回归。

### 路径 B（仅兜底：模拟器安装失败 / 本机不可用时切换）

- 交付全套代码 + 用例 + 报告模板 + 单条运行命令，你在 Android Studio / 真机跑通后回传测试报告 XML 与截图（或允许 agent 经 adb 复核）；切换前与你确认。

### 命令速查
```bash
./gradlew :app:connectedDebugAndroidTest                 # 全量
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=com.demo.trouter.MainRouterTest#testBasicNavigation
adb logcat -d -s TRouter                                  # 日志佐证（O1）
adb exec-out screencap -p > docs/reports/v1/<name>.png    # 截图
```
