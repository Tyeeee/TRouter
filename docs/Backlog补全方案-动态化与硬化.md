## 1. L4 洋葱/双向链（拦截器模型改造）

- 目标：拦截器不能只会"放行/拦截/改写"，还要能**把后续动作包起来**（前置逻辑 → 放行 → 后置逻辑），形成"洋葱"效果（请求往下钻、响应往外卷）。同时保留 V2（第二版）已有的 Continue/Block/Redirect 语义，不破坏调用方的代码。
- API 要点：
  ```
  interface RouteInterceptor {
      fun intercept(chain: RouterChain): InterceptorDecision
  }
  // chain 暴露：meta/bundle/当前索引/proceed(): 继续执行后续拦截器并最终打开目标
  // 每个拦截器可在 proceed() 前后做前置/后置（洋葱）；仍返回 Block/Redirect 语义
  ```
- 顺序/并发对策（吸取 RemoteRouter 的教训）：一次链执行是**单一调用栈、同步推进**；动态增删只影响"下一次 navigate 用的那份链快照"，绝不并发改写正在跑的链 → 所以每次 navigate 都先取一份**不可变快照**再执行。
- 回归用例（本项专属）：后置观察执行序（proceed 返回之后还会执行）、Block 短路时后置不执行、Redirect 与新链的语义、连续两次 navigate 互不串扰。

## 2. L2 动态增删拦截器

- `TRouter.addInterceptor(interceptor)` / `removeInterceptor(interceptor)`（按实例引用），再加查询能力。
- 线程安全：config.interceptors 改成**不可变列表快照**（CopyOnWrite 语义：navigate 取一份快照用，增删只在切换快照的那一刻生效；CopyOnWrite＝改的时候复制一份新的，读的人继续读旧的，互不影响）。
- 与 L4 的关系：注册表独立于"链执行"；改注册表绝不打断正在跑的链。
- 回归用例：导航过程中增删 → 下一次生效/失效（顺序断言）；并发增删 + 并发 navigate 不崩、结果确定。

## 3. L3 @Interceptor（注解级拦截）

- 注解的作用目标：`@Route` 页面声明自己要挂哪些拦截器标识；运行时注册表负责 `标识 → 拦截器实例` 的对应关系。
  ```
  @Interceptor(names = ["login", "audit"])   // 或合并进 @Route 扩展参数（开放项 O-L3）
  @Route(path = ...)
  ```
- 语义：这个目标的链 = 全局链 + 这个目标注解里写的链（谁在前：全局 → 目标附加？开放项 O-L3-顺序）；注册表里缺这个标识 = 编译期/运行期明确失败（不闷着当没写）。
- 用 KSP（KSP＝在编译期自动生成代码的工具）生成"目标拦截器标识清单"（沿用 aggregating=true，复用 CrossProcess 那套生成模式）。
- 回归用例：目标级拦截生效、没注册的标识明确失败、不是目标的路径不受影响。

## 4. F 动态路由热更 / 持久化

- 在 V5 的 `registerRoute/unregisterRoute` 之上再提供：
  - `applyRouteConfig(config)`：**原子批量应用**（一组合法 diff（diff＝这次要增删哪些路径的差异清单）要么全部成功、要么全部不做；要校验 path 合法性和是否重复，冲突策略和 V5 一致＝先移除再注册）；
  - 持久化：当前的动态路由集可以导出/导入（demo 用应用私有文件；把 RouteMeta 用 JSON 序列化成一串字符串）。
- 顺序/并发：apply 走单线程串行（复用 remote worker 的思路，或者单独做一个 routeConfig 串行器）；正在跑的 navigate 取一致快照。
- 回归用例：批量里有一条非法就整体回滚（原子性）、apply 之后 navigate 结果一致、重复 apply 幂等、导出→导入能还原一致。

## 5. L1 跨模块编译期冲突检测

- 现实约束（已经论证过）：KSP 一次只能看到自己这个模块，所以没法在单个 processor 内部做出"跨模块冲突就 ERROR"。
- 方案（确定性强，不动 KSP 架构）：**加一个构建期校验任务**——在宿主/聚合模块里注册一个 Gradle task，在各模块的 `kspDebugKotlin` 之后，去解析每个模块 `generated/GroupLoader_*.kt` 里的 path 常量，**发现跨模块重复就让构建失败**（把冲突双方和各来自哪个模块列出来）。运行时那条 duplicate 告警防线继续保留兜底（duplicate＝路径重复）。
- 回归用例：两个 feature 模块注入同一个 path → 有构建失败的证据；移除之后恢复正常。

## 6. D 动态代理（V4 增强）—— 需要你补语义

- "动态代理"这个词在 V4 roadmap 里没记细节，需要你确认到底指什么（开放项 O-D）：
  ① 用 Java/Kotlin 的动态代理把 AIDL binder 包一层（AIDL＝Android 提供的进程间通信方式；binder＝它用来传请求和结果的对象）→ host 拿到的 IRouter 是一个"感觉不到远程"的代理对象（远程调用被透明化，底层还是走 bound service）；
  ② 还是"代理进程/路由表"式的透明分发（调用某个 path 时自动决定本地执行还是远端执行）；
  ③ 其他（你本来的设想）。
- 我倾向 ①（工作量小、和既有通道是正交的、也是 backlog 里最自洽的解释），② 要动架构，得另外评估。
